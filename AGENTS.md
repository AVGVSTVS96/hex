# Working on hex

This repo is hex itself. A user's hex is their own folder (`~/hex`) with this repo cloned inside as `.hex/`; their sessions run in that folder, never in here. Nothing personal goes in this repo: no names, accounts, machines or memories.

- `HEX.md` is how the assistant works. Each user's `AGENTS.md` imports it, so write it to the assistant, in the user's voice.
- `defaults/` seeds a new user's folder (`bin/hex init`); updates don't copy it again (changing a seeded file takes `bin/migrate`), so anything every hex must get belongs in `HEX.md`, `plugin/` or `bin/`.
- `plugin/hooks/hooks.json` lists what runs in every session: the owner's profile and memory at start and after compaction (`bin/wake`; [OptMem](https://github.com/VictorTaelin/OptMem), downloaded by `bin/optmem`, never committed), the last turns after compaction (`bin/compacted`), the log of every message (`bin/log`), open tasks and questions (`hub/tasks.ts`), rule changes mid-session (`bin/rules`), and the memory agent after each turn (`hub/observe.ts`), which writes every note, its compressions and the profile.
- `hub/` gives every thread its own session (`bin/session` starts it) and keeps every message, task and question in `state/hex.db` (`hub/store.ts`). A DM's session, once spent, gives way to a fresh one that sees the chat as an [OptChat](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449) tree (`bin/chat`). `channels/` holds the clients: Telegram, Discord, Buzz, T3 Code and voice. Telegram and Discord began as [Anthropic's](https://github.com/anthropics/claude-plugins-official) and no longer follow it, so port an upstream fix by hand and run `bin/check` ([the old fork](https://github.com/AVGVSTVS96/claude-plugins-official) has each change's intent in a `PATCH.md`).
- `bin/job` runs long work as its own systemd unit that wakes its thread when it ends; a `claude` job runs as a hex session in the folder it was started from, and `bin/session` trusts the folder a background session starts in. `bin/update` ships hex only after `bin/check` passes and once no hex session is busy (`bin/quiet`).
- `computer/` sets up hex's own Fly.io Sprite, `bin/vault` is [enclave](https://github.com/AVGVSTVS96/enclave) plus typing on that computer (enclave owns the relay, page and store, so changes to them go there), and `media/` makes videos in `site/`'s look, keeping its colors and app mocks (`media/kit/apps.css`) in step with `site/style.css`.

microscope reviews every pull request: run `microscope review <number>` after opening it and after each push, then fix or answer what it finds. Merging needs its `microscope/correctness` status, and [CONTRIBUTING.md](CONTRIBUTING.md) has the rest of the flow.
